## Identity

A Master is a human trainer/player character who commands and calls monsters. Trainers, monsters, effects, environments, and interface assets are separate families. Compatibility-era IDs such as `warden-master-v1` may remain temporarily, but they do not define a monster species.

- [`core-pack-v1.md`](core-pack-v1.md) — runtime pack, identity layers, source-master lifecycle, legacy fallbacks, and validation.
- [`default-master-trainer-v1.md`](default-master-trainer-v1.md) — initial human-trainer source specification.

## Acceptance rule

An image is source material, not an integrated asset. Acceptance requires provenance, cleanup, retained source master, deterministic derivative, manifest registration, stable identity mapping, renderer integration, focused checks, and desktop/mobile visual inspection.

The product-wide registry controls production order. Narrow campaign or NPC work orders cannot redefine the whole asset roadmap.
